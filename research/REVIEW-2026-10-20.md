# Implementation review — 2026-10-20

The repository is a research-backed device-control prototype, not a full port.
Review scope: runtime transport, device methods, discovery, GTK callbacks,
button event capture/restoration, framing/schema tools, extraction/oracle scripts,
existing tests, captured official code, live hardware and the running Solaar setup.

## Findings and corrections

| Finding | Evidence | Correction / verification |
| --- | --- | --- |
| Haptic preview ignored the selected slider value | Original GUI callback only sent waveform 7; Apply feedback was separate | Apply and test now writes the selected level, verifies readback and then plays. Disabled feedback or failed readback prevents playback. |
| Haptic strength had not been physically verified | Earlier native tests compared parameter construction, and a pulse was felt, but no strength comparison had been confirmed | Read/write/restore at 10 and 90 passed. User explicitly confirmed the second pulse was clearly stronger in the ready-coordinated comparison. Original 60 restored. |
| Solaar could undo app changes | Saved mouse configuration had DPI 1000, haptic-level 60 and wheel/button values. Installed `settings.apply_all_settings` applies values unless sensitivity is `ignore`; device activation invokes it | Backed up config, stopped Solaar cleanly, marked only this mouse's seven overlapping settings ignored, restarted Solaar. Current DPI remained 1650 rather than resetting to 1000. |
| Reply identity overlapped Solaar | Our ID was 14; installed Solaar cycles IDs 2 through 15 | Default ID is now 1. Advisory device lock prevents overlapping operations by our own processes. Verified live request/reply traffic using ID 1. This does not establish compatibility with every third-party manager. |
| Already queued replies could satisfy a new request | Matching used only device/feature/function/software ID; no pre-request drain | Discard queued stale replies before sending; reject malformed report lengths. Socket-based transport regression checks cover stale, foreign-client and malformed replies. Replies arriving late after a timeout remain a general HID++ correlation limit; no blind mutation retry is added. |
| Button notifications were lost during requests | Request loop discarded unmatched incoming packets | Preserve notifications in a bounded queue and deliver them to the event reader. Tests cover press/release around a request. No full background dispatcher exists yet. |
| One optional read could hide an otherwise connected device | Discovery caught an error around the whole snapshot and skipped the device | Keep identity and successful fields, report individual read failures, and omit unavailable controls. UI tested with missing DPI range. |
| Device switching could race an in-flight operation | Sidebar stayed enabled during worker tasks | Disable selection while busy and reject duplicate queued UI work. |
| Long errors were hidden in the footer | Status label used ellipsizing | Wrap status text; report partial discovery failures explicitly. |
| Capture termination lacked a restoration attempt | Normal window close canceled capture, but SIGTERM could terminate immediately | GUI handles SIGINT/SIGTERM through normal close/cancellation; capture script turns SIGTERM into an exception through its finally block. Physical disconnection can still prevent restoration and is reported as an error. |
| Unknown mouse settings could show a keyboard label | Device type was inferred solely from a successful DPI read | Prefer the observed device kind; keyboard placeholder only for keyboard kind. |
| DPI slider accepted unsupported positions | Previous turn reproduced 1234 on a slider with device steps of 50 | Existing fix retained and re-tested: slider indices select only device-advertised values. |
| UI tests were insufficiently isolated and could not register multiple apps | Adding more widget tests exposed duplicate D-Bus registration; an invocation also inherited the desktop Wayland environment and crashed | Shared test application, private D-Bus session, forced X11 and explicit isolated-test marker. Three GTK callback/render tests now pass. Live UI harness already creates its own X server, session bus and XDG directories. |

The reply-ID collision was a demonstrated possibility, not a proven cause of the
user's symptom. The direct cause reproduced in the haptic UI was the preview
callback not applying the selected strength.

## Remaining gaps

- Actions Ring is absent. A thumb-pad notification is not an Actions Ring.
- No background agent, autostart, reconnect recovery, persistent app profiles,
  shortcut injection, gestures, Smart Actions, Flow, account sync or firmware UI.
- Keyboard customization is absent beyond basic inspection/battery.
- Scroll mode and button remapping have device readback evidence; complete
  physical behavior, auto-switch sensitivity, thumb wheel and per-app behavior
  have not been accepted as equivalent to Options+.
- Bluetooth, other receivers and other device models are not acceptance-tested.
- Current settings can depend on firmware persistence. Solaar ignore resolves
  conflicting writes but does not create a missing profile/persistence service.
- Temporary diversion restoration requires a reachable device. No reconnect
  restoration journal or daemon has been implemented.
- Original-code differentials validate specific methods/bytes, not the full
  agent or UI. Most protocol operations still lack original-code differential
  coverage beyond the retained disassembly and physical traffic replay.
- Research fixtures and proprietary binaries are local ignored artifacts; tests
  that need them skip when absent. A plain passing test count must not be
  described as complete behavior or feature parity.
